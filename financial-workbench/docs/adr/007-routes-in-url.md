## ADR-007: 화면 상태를 경로와 query 로 주소에 두고 React Router 로 다룬다

- **status**: `accepted`
- **결정**: 화면은 경로로(목록은 [흐름](../flow.md) 의 「주소와 뒤로가기」), 연 항목과 검색 조건 같은 화면 상태는 query 로 주소에 둔다. 웹은 React Router 8(경로와 query 만 쓰는 단순 모드)로 주소를 읽고 바꾼다. 서버는 API 가 아닌 화면 경로를 `index.html` 로 돌려준다.
- **대체된 부분**: 경로 목록과 상단 탭 구성은 [ADR-010](010-concept-map-first-screen.md) 이 바꿨다(`/map` 추가, `/` 는 `/map` 으로 연다, 상단 탭은 셋이고 나머지는 더보기 메뉴). 주소 규칙은 그대로다.
- **맥락**: 지금은 어느 탭이든 주소가 `/` 이고 화면 상태가 React 상태에만 있다. 그래서 뒤로가기를 누르면 앱 밖으로 나가고, 새로고침하면 보던 탭과 항목이 사라지고, 탭을 옮겼다 돌아오면 검색 조건이 처음으로 돌아간다(2026-10-22 사용자 요청 「뒤로가기 시 동작이 어색하다」). 검토를 부탁하는 링크(`/?node=<id>`)는 이미 밖으로 나가 있어 계속 열려야 한다.
- **대안 기각**:
  - `/` 에 query 만 두고 history API 를 직접 다루는 안: 새 의존과 서버 수정이 없지만, 주소가 화면 구조를 드러내지 않고 탭이 늘 때마다 직접 짠 코드를 고쳐야 한다. 사용자가 경로별 주소를 골랐다.
  - TanStack Router: query 값의 타입 검사가 강하지만 경로 정의 방식과 설정이 커서, 탭 여섯 개짜리 화면에는 얻는 것보다 배울 것이 많다.
  - wouter: 작지만 query 다루기와 이동 막기를 직접 짜야 한다.
- **결과**:
  - 얻는 것: 뒤로가기와 앞으로가기가 탭 이동, 항목 열기, 좁은 화면의 검색, 그래프, 상세 탭 사이를 오간다. 새로고침과 링크가 보던 화면을 다시 연다. 탭을 옮겼다 돌아와도 주소에 남은 검색 조건이 그대로다.
  - 감당할 것: 화면 경로가 공개 계약이 된다. 경로나 query 이름을 바꾸면 이미 보낸 링크가 깨지므로 옛 형식을 넘겨주는 처리를 남긴다. 서버의 화면 경로 목록과 웹의 경로 목록을 함께 고쳐야 한다. 그래프를 넓힌 결과(이웃 확장으로 더한 노드)는 주소에 담지 않아 뒤로가기로 돌아오면 중심 노드의 주변만 다시 읽는다.
- **적용 범위**: `financial-workbench/web/src/`, 서버의 화면 경로 처리. 경로와 query 이름은 [흐름](../flow.md) 의 「주소와 뒤로가기」 가 소유한다.
