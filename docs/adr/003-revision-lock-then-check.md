## ADR-003: revision 비교 전에 대상 노드에 쓰기 잠금을 건다

- **status**: `accepted`
- **결정**: 수정, 검토, 보관, 복원은 한 트랜잭션에서 대상에 쓰기를 먼저 해 잠금을 쥐고(`SET n._lock = true`), 그 뒤에 revision 을 읽어 `expectedRevision` 과 비교한다. 같으면 갱신하고 revision 을 올리고 ChangeEvent 를 만든다. 다르면 예외로 롤백하고 409 를 낸다.
- **맥락**: 두 사용자가 같은 revision 을 고치면 첫 저장만 성공해야 한다. Neo4j 의 기본 격리 수준은 read committed 다. `MATCH ... WHERE n.revision = $expected SET ...` 한 쿼리는 `WHERE` 를 평가한 뒤에 쓰기 잠금을 기다리므로, 두 트랜잭션이 모두 조건을 통과하고 차례로 덮어쓸 수 있다.
- **대안 기각**:
  - 조건부 `SET` 한 쿼리: 위 경합에서 갱신 손실이 생긴다.
  - APOC `apoc.lock.nodes`: Community 이미지에 APOC 를 따로 넣어야 한다.
  - 애플리케이션 메모리 잠금: API 인스턴스가 둘 이상이면 깨지고, 트랜잭션과 범위가 맞지 않는다.
- **결과**:
  - 얻는 것: 동시 수정이 덮어쓰기 대신 409 가 된다. 데이터와 이력이 함께 커밋된다.
  - 감당할 것: 모든 쓰기가 같은 노드에 대해 직렬화된다. 두 사람 규모에서는 대기가 짧다. 잠금 표시 속성 `_lock` 은 커밋 전에 지우므로 저장되지 않는다. 동작은 실제 Neo4j 를 띄운 동시 수정 테스트로 확인한다.
