## ADR-005: 온톨로지는 Git 의 YAML 로 관리하고 API 가 쓰기를 검증한다

- **status**: `superseded`
- **결정**: 허용 노드 타입, 속성과 타입, 필수 여부, 허용 관계와 시작·끝 타입, Claim predicate 와 대상 타입, 화면에 보일 표시 이름, 스키마 버전을 `ontology/financial-ontology.yaml` 에 둔다. API 는 빌드 때 이 파일을 jar 에 담고, 시작할 때 읽어 모든 쓰기를 검증한다. Cypher 문자열에 넣는 label 과 관계 타입도 이 파일의 허용 목록에서만 고른다.
- **대체된 부분**: 「Git 의 YAML 로 관리한다」 와 「웹은 정의를 읽기만 한다」 는 [ADR-008](008-ontology-versions-in-db.md) 이 대체했다(2026-10-23). 온톨로지는 DB 에 버전으로 쌓고 ADMIN 이 웹에서 편집한다. 「API 가 쓰기를 검증하고 Cypher 에 넣는 이름은 허용 목록에서만 고른다」 는 그대로 유효하다.
- **맥락**: 온톨로지 변경은 드물고 리뷰가 필요하다. Neo4j Community 는 속성 타입 제약과 관계 끝점 제약을 집행하지 않는다.
- **대안 기각**:
  - 온톨로지를 Neo4j 노드로 저장하고 웹에서 편집: 편집 화면과 버전 관리, 기존 데이터 이전 절차가 필요하다. 첫 마일스톤 범위 밖이다.
  - Neo4j 제약 조건으로 집행: Community 에서 쓸 수 있는 것은 유일성 제약 정도다.
- **결과**:
  - 얻는 것: 정의가 코드 리뷰를 거친다. 서버 한 곳에서 검증한다. 타입과 속성이 늘어도 웹 코드를 고치지 않고 YAML 의 표시 이름만 더하면 된다. 로더가 알 수 없는 키를 거절하므로 잘린 값이 화면까지 가지 않는다.
  - 감당할 것: 온톨로지를 바꾸려면 PR 과 재배포가 필요하다. 바꾼 정의가 기존 데이터와 맞는지는 사람이 확인한다. 웹은 정의를 읽기만 한다.
