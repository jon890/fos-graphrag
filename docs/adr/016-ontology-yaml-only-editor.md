## ADR-016: 온톨로지는 웹의 YAML 편집기 하나로만 고친다

- **status**: `accepted`
- **결정**: 웹의 온톨로지 편집기는 YAML 편집기 하나다. 폼 편집기와 「폼으로 편집」, 「폼으로 보기」 를 지운다. 예전 주소 `/ontology?view=form` 은 `?view=yaml` 로 바꿔 연다. YAML 편집기는 화면 높이에 맞춘 줄 번호 있는 편집칸과, 스크롤해도 보이는 툴바(「저장 전에 확인」, 「초안 버리기」, 「버전 기록」, 「YAML 내려받기」, 초안 상태, 도움말)를 둔다. 미리보기 결과는 편집칸 옆(넓은 화면)이나 아래 접힘 칸(좁은 화면)에 띄운다. 새 의존은 넣지 않고 HTML 기본 `<textarea>` 와 줄 번호 칸으로 만든다.
- **ADR-008 과의 관계**: [ADR-008](008-ontology-versions-in-db.md) 의 「ADMIN 만 웹의 폼 편집기와 YAML 편집기로 고친다」 가운데 폼 편집기를 이 결정이 뺀다. 버전 저장, 코드 소유 부분, 미리보기와 영향 확인은 그대로다.
- **맥락**: 사용자는 폼 편집기가 복잡해 쓰지 않고 YAML 로만 고친다(사용자 결정 2026-10-26). 고치는 일은 대부분 Claude Code, Codex 같은 에이전트에 맡기고, 에이전트는 YAML 전체를 받아 고친다([ADR-017](017-agent-ontology-and-instance-proposals.md)). 예전 YAML 편집칸은 내용 길이만큼 늘어나 운영에서 약 2만 px 가 됐고, 「저장 전에 확인」 과 「초안 버리기」 가 맨 아래에 있었다. 폼과 YAML 이 초안 하나를 함께 쓰느라 초안이 두 모양(`yaml`, `definition`)을 오가며 미리보기 API 로 바뀌었다.
- **대안 기각**:

  | 대안 | 기각 이유 |
  | --- | --- |
  | 폼 편집기를 남기고 숨긴다 | 쓰지 않는 화면의 코드, 단위 테스트, e2e 가 남아 초안 모양 변경마다 함께 고쳐야 한다 |
  | CodeMirror 6 으로 편집칸을 만든다 | 줄 번호, 구문 색, 접기를 얻지만 의존이 늘고 번들이 커진다. 실행 중에 `<style>` 을 넣어 `style-src 'self'` 와 부딪힐 수 있다. 필요한 것은 줄 번호와 줄 이동뿐이다 |
  | Monaco 편집기 | 번들이 몇 MB 이고 웹 워커를 띄운다. 두 사람이 쓰는 도구의 YAML 한 파일에 비해 크다 |
  | 편집칸을 늘이고 툴바만 아래에 고정한다 | 페이지 스크롤이 남아 미리보기 결과와 오류 줄을 오가기 어렵다 |

- **결과**:
  - 얻는 것: 초안이 YAML 문자열 하나라 폼과 YAML 을 오가는 변환이 사라진다. 툴바와 미리보기 결과가 늘 보이고, 검증 오류의 줄 번호를 누르면 그 줄로 간다.
  - 감당할 것: 사람이 웹에서 고칠 때는 YAML 문법을 알아야 한다. 도움말이 키 설명과 따옴표 규칙을 맡는다. 구문 색과 자동 들여쓰기는 없다. 편집칸은 줄을 접지 않으므로 긴 줄은 가로로 스크롤한다.
- **적용 범위**: 화면 규칙은 [흐름](../flow.md) 의 「온톨로지 편집」, 부품 배치는 [코드 구조](../code-architecture.md) 의 「웹 구조」 가 소유한다.
