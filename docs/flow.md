# 실행 흐름

## 정상 흐름

1. 사용자가 `.env`에 Neo4j 접속 정보를 설정한다.
2. `docker compose up -d`가 Neo4j를 시작한다.
3. 컨테이너의 상태 확인이 Cypher 쿼리로 준비 완료를 판정한다.
4. 사용자가 연결 확인 명령을 실행한다.
5. Python 애플리케이션이 공식 드라이버로 연결과 인증을 확인한다.
6. 성공 메시지에 접속 주소와 데이터베이스 이름을 표시한다.

## 실패 흐름

- 필수 환경변수가 없으면 종료 코드 `2`와 누락된 변수명을 출력한다.
- 주소, 인증, 네트워크에 문제가 있으면 종료 코드 `1`과 연결 오류를 출력한다.
- 비밀번호는 성공·실패 메시지와 설정 객체 표현에 노출하지 않는다.

## 빈 상태와 충돌

그래프 데이터가 없어도 연결 확인은 성공해야 한다.

설정한 호스트 포트를 다른 프로세스가 사용 중이면 컨테이너 시작 단계에서 실패한다.
이 경우 `.env`의 포트와 `NEO4J_URI`를 함께 조정한다.

## 로컬 모델 연결 흐름

1. 사용자가 호스트에서 Ollama를 시작한다.
2. `nemotron-3-nano:4b` 모델을 내려받는다.
3. 사용자가 모델 연결 확인 명령을 실행한다.
4. Python 애플리케이션이 `ChatOllama`로 짧은 한국어 메시지를 보낸다.
5. 비어 있지 않은 응답을 모델명과 함께 출력한다.

Ollama가 실행 중이 아니거나 모델이 설치되지 않았으면 종료 코드 `1`과 원인을 출력한다.
모델이 빈 응답을 반환해도 실패로 판정한다.

## 로컬 임베딩 연결 흐름

1. 사용자가 호스트에서 Ollama를 시작한다.
2. `qwen3-embedding:0.6b` 모델을 내려받는다.
3. 사용자가 임베딩 연결 확인 명령을 실행한다.
4. Python 애플리케이션이 `OllamaEmbeddings`로 한국어 예문을 변환한다.
5. 벡터가 비어 있지 않고 1,024차원인지 확인한 뒤 모델명과 차원을 출력한다.

Ollama가 실행 중이 아니거나 모델이 설치되지 않았으면 종료 코드 `1`과 원인을 출력한다.
빈 벡터나 설정과 다른 차원의 벡터도 실패로 판정한다.
연결 확인은 벡터를 Neo4j에 저장하지 않으므로 그래프가 비어 있어도 성공할 수 있다.
