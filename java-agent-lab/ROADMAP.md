# Java 에이전트 실습 가이드

이 문서는 학습 순서와 단계별 완료 기준을 정의한다.
각 단계를 직접 구현할 수 있도록 완성된 예제 코드는 제공하지 않는다.

## Spring AI Ollama 연결

목표: 애플리케이션이 설정된 Ollama 주소와 모델명을 사용할 수 있는지 확인한다.

확인할 개념:

- Spring AI Ollama 자동 구성
- 채팅 모델 선택
- 기본 URL 설정
- 모델 다운로드 전략

완료 기준: 로컬 검증으로 설정 바인딩을 확인하고, 실제 모델 호출은 Ollama가 실행 중일 때만 수행한다.

## 에이전트 상태와 채널

목표: 분기나 도구를 추가하기 전에 그래프에서 데이터가 이동하는 방식을 표현한다.

확인할 개념:

- 상태 키
- 채널 병합 규칙
- 불변 상태 갱신과 가변 상태 갱신의 차이

완료 기준: 상태 갱신이 명시적으로 표현되고 단위 테스트에서 결과를 확인할 수 있다.

## 단일 노드 그래프

목표: 하나의 변환만 수행하는 가장 작은 그래프를 작성한다.

확인할 개념:

- 그래프 빌더 설정
- 노드 동작 계약
- 컴파일 단계
- 실행 결과

완료 기준: 노드 하나가 초기 상태를 받아 갱신된 상태를 반환하며 이를 집중된 테스트로 검증한다.

## 엣지와 조건부 분기

목표: 명확한 조건에 따라 상태를 여러 단계로 전달한다.

확인할 개념:

- 일반 엣지
- 조건부 라우팅
- 종료 상태
- 분기 이름

완료 기준: 두 개 이상의 경로를 테스트하고 각 경로가 예상한 종료 결과에 도달함을 증명한다.

## 체크포인트와 대화 상태

목표: 여러 번 실행해도 그래프 상태를 유지한다.

확인할 개념:

- 체크포인트 저장소
- 스레드 또는 대화 식별자
- 실행 재개 동작

완료 기준: 전체 이력을 수동으로 다시 만들지 않고 저장된 상태에서 다음 실행을 이어간다.

## 도구 호출

목표: 통제된 도구 경계를 그래프에 연결한다.

확인할 개념:

- 도구 입력 형식
- 출력 검증
- 오류 처리
- 재시도 또는 대체 정책

완료 기준: 테스트에서 도구 동작이 결정적이며 실패가 숨은 부수 효과가 아니라 상태로 드러난다.

## 사람 승인 중단과 재개

목표: 민감한 동작 전에 실행을 멈추고 승인 데이터가 제공되면 재개한다.

확인할 개념:

- 중단 지점
- 승인 데이터 형식
- 저장된 상태
- 재개 전이

완료 기준: 그래프가 민감한 단계 전에 멈추고 대기 결정을 기록하며 명시적 승인 결과로만 재개한다.

## 하위 그래프 또는 다중 에이전트

목표: 큰 흐름을 더 작은 그래프 책임으로 나눈다.

확인할 개념:

- 하위 그래프 경계
- 상태 투영
- 전달 데이터
- 최종 출력 소유권

완료 기준: 각 그래프가 좁은 책임을 가지며 통합 테스트가 전달 동작을 증명하고 공유 상태 필드가 문서화되어 있다.
