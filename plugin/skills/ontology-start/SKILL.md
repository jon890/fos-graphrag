# 가치투자 온톨로지 시작하기

**목표: 사용자가 로그인을 마치고, 지금 무엇을 할 수 있는지 알고, 원하면 첫 데이터를 올리는 데까지 간다.**

## 순서

| 단계 | 할 일 | 다음으로 가는 조건 |
| --- | --- | --- |
| 1 | `get_connection` 을 부른다 | 결과가 오거나, 인증이 필요하다는 응답이 온다 |
| 2 | 누구로 붙었는지 알린다 | 표시 이름, 역할, 범위를 말했다 |
| 3 | 범위가 조회만이면 다시 연결하게 한다 | 「조회와 기록」 으로 연결됐다 |
| 4 | `get_ontology` 로 지금 온톨로지를 보인다 | 다섯 줄 안으로 말했다 |
| 5 | 할 수 있는 일을 알린다 | 예시 문장을 보였다 |
| 6 | 첫 데이터 추가를 함께 해 본다 | 사용자가 원하지 않으면 건너뛴다 |

## 1. 연결 확인

`get_connection` 을 부릅니다.
사용자가 아직 아무것도 설정하지 않았어도 먼저 부릅니다. 로그인 창은 도구를 부르면 열립니다.

도구가 인증을 요구하거나 실패하면 이 한 문장만 말합니다.

> 브라우저가 열리면 Google 로 로그인하고 「연결 허용」 을 누르세요.

사용자가 로그인을 마쳤다고 하면 `get_connection` 을 다시 부릅니다.

브라우저가 열리지 않는다고 하면 쓰는 도구에 맞게 안내합니다.

- Claude Code: `/mcp` 를 입력해 목록에서 `valuation-ontology` 를 고르고 로그인을 누르세요.
- Codex: 터미널에서 `codex mcp login valuation-ontology` 를 실행하세요.

「접근 권한이 없습니다」 라고 나오면 관리자에게 본인의 Gmail 을 추가해 달라고 부탁하게 안내합니다.

## 2. 누구로 붙었는지

결과의 표시 이름, 역할, 범위를 한 줄로 알립니다.

- 역할: `VIEWER` 는 「열람자」, `EDITOR` 는 「편집자」, `ADMIN` 은 「관리자」 라고 말합니다.
- 범위: `READ` 는 「조회만」, `READ_WRITE` 는 「조회와 기록」 이라고 말합니다.

역할이 `ADMIN` 이 아니면 이 말을 덧붙입니다.

> 온톨로지 정의를 바꾸려면 관리자 역할이 필요합니다. 관리자에게 내 역할을 관리자로 바꿔 달라고 부탁하세요.

## 3. 조회만 연결일 때

범위가 `READ` 면 이렇게 안내합니다.

> 웹 앱의 「더보기 → 연동」 에서 이 연결을 끊고, 다시 로그인해서 「조회와 기록」 을 고르세요.

다시 연결했다고 하면 1 단계부터 합니다.
기록 도구가 「조회만 허락된 연결」 이라고 거절할 때도 같은 안내를 합니다.

## 4. 지금 온톨로지 한눈에 보기

`get_ontology` 를 부르고 다섯 줄 안으로 말합니다.

- 버전
- 항목 종류 몇 가지와 그 표시 이름
- 관계 몇 가지와 문장 틀

## 5. 할 수 있는 일

세 가지를 예시 문장과 함께 보입니다.

- 조회: 「안전마진이 뭐야」, 「FLNC 투자 근거 보여줘」, 「내 공부 목록 보여줘」
- 데이터 추가: 「FLNC 에 근거 문서를 이어 줘」
- 온톨로지 수정: 「온톨로지에 새 종류 더해 줘」

사용자의 역할로 승인할 수 없는 일이 있으면 그 일 옆에 「내 역할로는 승인할 수 없습니다」 와 필요한 역할을 적습니다.
데이터 추가의 승인에는 편집자, 온톨로지 수정의 승인에는 관리자 역할이 필요합니다.

## 6. 첫 데이터 추가 해 보기

사용자가 원하면 `ontology-record` 의 순서로 항목 하나(예: 개념 하나)를 제안으로 올리고, 「더보기 → 제안」 에서 승인하는 위치까지 안내합니다.
원하지 않으면 건너뜁니다.

## 말하는 방식

- 다음에 할 일만 한두 문장으로 말합니다.
- 토큰, 인증 방식 같은 내부 이야기는 꺼내지 않습니다.
- 어떤 종목을 사라거나 팔라는 말은 하지 않습니다.
