Lesson 05

조건부 Edge

노드 안에 다음 단계를 숨기지 않고, 현재 상태를 기준으로 그래프가 경로를 선택하게 한다.

EdgeAction라우팅분기 테스트
오늘의 한 문장
조건부 Edge는 상태를 바꾸는 로직이 아니라 다음 노드를 고르는 로직이다.

1부 · 개념 학습

고정 Edge와 조건부 Edge

고정 Edge

현재 Node가 끝나면 항상 미리 정한 하나의 Node로 이동한다.

조건부 Edge

현재 State를 확인한 결과에 따라 여러 목적지 중 하나를 선택한다.

조건부 Edge는 어떻게 목적지를 고를까?

라우팅 함수는 현재 State를 읽고 경로를 나타내는 이름을 반환한다. 그래프에 등록된 경로 매핑이 그 이름을 실제 목적지 Node와 연결한다. 라우팅 함수가 Node를 직접 실행하는 것은 아니다.

현재 State ↓ 라우팅 조건 판단 경로 이름 반환 ↓ 그래프의 경로 매핑 조회 다음 Node 선택

Node와 라우팅 책임을 나눈다

Node는 상태를 계산하고 갱신한다. 조건부 Edge의 라우팅 함수는 갱신된 상태를 읽어 다음 위치만 결정한다. 이 구분을 지키면 비즈니스 처리와 실행 흐름을 각각 독립적으로 테스트할 수 있다.

실습 예제에 적용한다

정규화된 요구사항이 비어 있으면 종료하고, 유효하면 검토 Node로 이동하는 두 경로를 만든다.

2부 · 실습 가이드

추가할 분기

요구사항이 비어 있으면 더 진행하지 않고 종료한다. 유효한 요구사항이면 검토 노드로 이동한다.

┌─ invalid → END START → normalize ─┤ └─ valid → review → END

직접 타이핑할 순서

  1. 분기 결과를 나타낼 이름 두 개를 정한다.
  2. 현재 상태를 받아 분기 이름을 반환하는 Edge 동작을 만든다.
  3. 분기 이름과 목적지 노드의 매핑을 그래프에 등록한다.
  4. 유효 입력과 빈 입력이 서로 다른 경로를 타는지 테스트한다.
  5. 각 경로의 최종 상태가 어떻게 다른지 검증한다.

완료 조건

  • 라우터는 상태를 변경하지 않는다.
  • 두 분기 모두 종료 지점에 도달한다.
  • 분기 이름과 노드 이름을 혼동하지 않는다.
  • 두 경로가 각각 하나 이상의 테스트로 고정되어 있다.

생각할 질문

  • 조건 검사를 Node에서 하는 것과 Edge에서 하는 것은 책임이 어떻게 다른가?
  • 라우터가 Boolean 대신 이름을 반환하면 무엇이 더 명확해지는가?
  • 새 분기가 추가될 때 어떤 테스트가 필요할까?
막혔을 때 확인할 것
EdgeAction<PlanningState>와 addConditionalEdges(...)의 역할을 분리해서 본다.
