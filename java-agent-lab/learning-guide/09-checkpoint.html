Lesson 09

Checkpoint와 재개

실행 중간의 상태를 저장하고, 동일한 작업 식별자로 이력을 조회하거나 이어서 실행한다.

오늘의 한 문장
Checkpoint는 대화 메시지만 저장하는 메모리가 아니라 그래프 실행 상태의 이력이다.

이번 단계의 범위

먼저 메모리 기반 저장소로 동작을 익힌다. 데이터베이스 저장소는 저장·조회·재개 계약을 이해한 뒤 교체한다.

직접 타이핑할 순서

  1. 그래프 컴파일 설정에 메모리 기반 CheckpointSaver를 연결한다.
  2. 실행 설정에 작업을 구분할 threadId를 넣는다.
  3. 같은 그래프를 서로 다른 두 스레드로 실행한다.
  4. 각 스레드의 최신 상태와 상태 이력을 조회한다.
  5. 같은 스레드에서 상태를 갱신하거나 실행을 이어간다.
  6. 다른 스레드의 상태가 섞이지 않는지 테스트한다.

완료 조건

  • 동일한 그래프 인스턴스에서 스레드별 상태가 분리된다.
  • 최종 상태뿐 아니라 중간 상태 이력을 조회할 수 있다.
  • 상태 크기가 커질 때 저장 비용이 커지는 이유를 설명할 수 있다.
  • 메모리 저장소의 재시작 한계를 알고 있다.

생각할 질문

  • threadId는 사용자 ID, 대화 ID, 작업 ID 중 무엇이어야 할까?
  • 문서 원문 전체를 상태에 저장하면 어떤 비용이 생길까?
  • 재실행과 재개의 차이는 무엇인가?
막혔을 때 확인할 것
CompileConfig, CheckpointSaver 연결 지점, RunnableConfig의 스레드 식별자만 먼저 확인한다.
