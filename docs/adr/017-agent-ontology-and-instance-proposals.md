## ADR-017: 에이전트가 온톨로지 정의와 인스턴스를 바꾸는 일도 제안으로 받는다

- **status**: `accepted`
- **결정**: 제안 종류에 온톨로지 변경(`ONTOLOGY_CHANGE`)과 인스턴스 변경(`UPDATE_NODE`, `ARCHIVE_NODE`, `ARCHIVE_RELATIONSHIP`, `CREATE_CLAIM`)을 더한다. `ONTOLOGY_CHANGE` 의 내용은 바꾼 온톨로지 전체(YAML 이나 JSON 정의)와 기준 버전이다. 올릴 때 서버가 미리보기와 같은 검사를 해 틀린 정의와 낡은 기준 버전은 바로 거절한다. 승인은 ADMIN 만 하고, 승인하면 웹 저장과 같은 `OntologyEditService.save` 로 새 버전을 만든다. 기준 버전이 지금 버전과 다르면 승인하지 않는다. 덮어쓰지 않으려는 것이다. 원격 MCP 에 지금 온톨로지 YAML 을 받는 도구(`get_ontology_yaml`)와 온톨로지 변경을 올리는 도구(`propose_ontology_change`)를 더하고, 같은 서비스를 쓰는 `/api/v1` 도 새 종류를 받는다. 제안은 지금처럼 올린 사람의 것이고 주인만 승인한다.
- **ADR-013 과의 관계**: [ADR-013](013-owner-trades-and-agent-proposals.md) 의 「사실은 바로 저장하고 해석은 제안으로 받는다」 와 「승인하면 기존 서비스로 실행한다」 를 그대로 따른다. 이 결정은 제안의 대상을 공유 지식 만들기에서 고치기, 보관, 주장 만들기, 온톨로지 정의로 넓힌다.
- **맥락**: 친구는 비개발자이고 Claude Code 와 Codex 를 1순위로 쓴다(사용자 결정 2026-10-26). 원격 MCP 로 조회와 만들기 제안은 됐지만, 고치기와 보관, 주장 만들기, 온톨로지 변경은 웹에서 직접 해야 했다. 에이전트가 공유 지식을 바꾸는 일은 사람이 승인한다는 규칙(ADR-013)을 지키면서 친구가 대화만으로 끝까지 할 수 있어야 한다. 온톨로지 YAML 은 운영에서 수십 KiB 라 에이전트의 한 번 호출에 들어간다.
- **대안 기각**:

  | 대안 | 기각 이유 |
  | --- | --- |
  | 에이전트가 온톨로지를 바로 저장한다 | 기존 데이터와 어긋나는 변경이 영향 확인 없이 들어간다. 영향 확인란을 누를 사람이 없다 |
  | 바뀐 부분만 담은 패치(JSON Patch)로 받는다 | 모델이 경로를 틀리기 쉽고, 서버가 패치를 적용하는 코드와 그 검사를 새로 만들어야 한다. 웹 저장이 이미 전체 정의를 받는다 |
  | 기준 버전이 달라도 지금 버전 위에 승인한다 | 그 사이 다른 사람이 저장한 변경이 제안의 옛 정의로 되돌아간다. 화면은 이 위험을 「뺌」 으로만 보여 준다 |
  | 온톨로지 변경 제안을 모든 ADMIN 이 보는 공용 목록에 둔다 | 제안의 주인 모델(주인만 읽고 승인)을 종류마다 다르게 만들어야 한다. 친구가 ADMIN 이면 본인이 승인한다 |
  | 인스턴스 고치기와 보관을 MCP 쓰기 도구로 바로 한다 | 모델의 해석이 공유 지식을 사람 확인 없이 바꾼다(ADR-013 의 기각 사유와 같다) |

- **결과**:
  - 얻는 것: 친구는 대화로 온톨로지와 인스턴스를 고치고, 웹의 「제안」 에서 바뀐 점과 영향을 보고 승인한다. 승인으로 생긴 버전과 노드 변경은 기존 변경 이력에 승인한 사람으로 남는다. 서버의 검증 코드는 웹 저장과 한 벌이다.
  - 감당할 것: `/mcp` 와 `/api/v1/proposals` 의 본문 상한을 온톨로지 저장과 같은 512KiB 로 올린다. 큰 제안이 대기 목록에 쌓일 수 있어 대기 200개 상한이 그대로 막는다. 온톨로지 변경 제안은 올린 뒤 누군가 저장하면 승인할 수 없게 되고, 에이전트가 지금 버전에서 다시 만들어야 한다. 고치기와 보관 제안은 올릴 때의 `revision` 을 담아, 그 사이 노드가 바뀌면 승인이 `409 REVISION_CONFLICT` 로 실패한다. 에이전트가 만든 주장의 작성자는 승인한 사람이라, 그 주장은 다른 사람이 검토한다.
- **적용 범위**: 계약은 [API 계약](../api-contract.md) 의 「제안」, 「에이전트 API(`/api/v1`)」 의 「쓰기」, 「원격 MCP(`/mcp`)」 의 「도구」, 저장 모델은 [데이터 스키마](../data-schema.md) 의 「제안」, 화면과 흐름은 [흐름](../flow.md) 의 「제안」 과 「에이전트 쓰기」 가 소유한다.
