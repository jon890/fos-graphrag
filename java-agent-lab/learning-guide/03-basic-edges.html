Lesson 03

START와 END

노드 하나를 실행 가능한 그래프로 감싸고, 컴파일이 하는 일을 확인한다.

StateGraphSTARTENDcompile
오늘의 한 문장
Edge는 실행 순서를 표현하고, 컴파일은 그 구조가 실행 가능한지 검증한다.

1부 · 개념 학습

Edge는 Node 사이의 이동 규칙이다

Edge는 네트워크 연결이나 데이터를 저장하는 객체가 아니다. 한 Node가 끝난 다음 어느 Node를 실행할지 그래프 구조에 표현하는 전이다. Node 안에서 다음 Node를 직접 호출하지 않기 때문에 실행 흐름을 따로 볼 수 있다.

START와 END는 그래프의 경계다

START

초기 State가 들어왔을 때 처음 실행할 Node로 연결하는 가상의 시작점이다.

END

더 실행할 Node가 없고 현재 State를 결과로 반환한다는 가상의 종료점이다.

둘 다 직접 작성하는 비즈니스 Node가 아니라 그래프의 입구와 출구를 나타내는 예약된 경계다.

설계도와 실행 객체는 구분된다

StateGraph

State 스키마, Node, Edge를 등록하는 그래프 설계도다.

CompiledGraph

설계도를 검증해 실제로 실행할 수 있게 만든 결과다.

컴파일 과정은 존재하지 않는 Node를 가리키는 Edge처럼 구조적인 문제를 실행 전에 발견하는 경계다.

2부 · 실습 가이드

만들 그래프

START → normalize_request → END

직접 타이핑할 순서

  1. PlanningState를 생성할 상태 팩터리를 준비한다.
  2. 상태 스키마와 팩터리로 StateGraph를 만든다.
  3. 정규화 노드를 이름과 함께 등록한다.
  4. START에서 노드로, 노드에서 END로 엣지를 연결한다.
  5. 그래프를 컴파일하고 초기 상태를 넣어 실행한다.
  6. 최종 상태에서 정규화 결과를 검증한다.

의도적으로 해볼 실패

노드 등록 누락

등록하지 않은 이름을 엣지에서 참조하고 컴파일 오류가 어디에서 발생하는지 본다.

종료 엣지 누락

끝으로 갈 수 없는 구조가 어떤 검증 결과를 만드는지 확인한다.

완료 조건

  • 가장 작은 그래프가 컴파일된다.
  • 초기 상태가 노드를 거쳐 최종 상태로 변한다.
  • 노드 테스트와 그래프 통합 테스트의 책임이 구분된다.
  • 노드 이름을 여러 곳에 오타 내기 쉬운 문자열로 반복하지 않는다.

생각할 질문

  • StateGraph와 CompiledGraph의 역할은 어떻게 다른가?
  • START와 첫 노드는 왜 같은 개념이 아닌가?
  • 그래프 구조 오류를 실행 시점보다 컴파일 시점에 발견하면 무엇이 좋아지는가?
