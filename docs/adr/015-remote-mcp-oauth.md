## ADR-015: 서버가 원격 MCP 를 직접 제공하고, 비개발자는 OAuth 로그인으로 Claude Code 와 Codex 를 붙인다

- **status**: `accepted`
- **결정**: API 서버가 `/mcp` 에서 원격 MCP(Streamable HTTP, 세션 없는 방식)를 제공한다. 도구 구현은 이 서버 한 곳에만 두고, 도구는 `/api/v1` 컨트롤러가 부르는 서비스를 그대로 부른다. 자기 `/api/v1` 을 HTTP 로 다시 부르지 않는다. 같은 서버가 MCP 인증 규격의 OAuth 인가 서버를 겸한다: 보호 자원 메타데이터(RFC 9728), 인가 서버 메타데이터(RFC 8414), 클라이언트 동적 등록(RFC 7591), 인가 코드와 PKCE(S256 만), resource 지시자(RFC 8707), 사용할 때마다 바꾸는 갱신 토큰이다. `/mcp` 는 `Authorization: Bearer` 로 이 서버가 발급한 OAuth 접근 토큰(`fwa_`)과 개인 연동 토큰(`fwb_`)을 둘 다 받는다. 플러그인(MCP 연결 설정과 스킬)은 이 저장소의 `plugin/` 에서 관리한다(사용자 결정 2026-10-26).
- **맥락**: 친구는 개발자가 아니라 API 토큰을 모른다. Claude Code 나 Codex 에 플러그인을 설치하고 스킬의 안내만 따라 가치투자 온톨로지를 조회하고 기록할 수 있어야 한다. 지금의 Hermes 커넥터(fos-assistant)는 사용자 컴퓨터에서 도는 TypeScript MCP 서버라 Node 나 Bun 이 필요하다. 설치 프로그램으로 받은 Claude Code 나 Codex 에는 둘이 없을 수 있다. 두 클라이언트는 원격 MCP 에 처음 도구를 부를 때 `401` 과 `WWW-Authenticate` 를 받으면 브라우저를 열어 OAuth 로그인을 하고, 클라이언트 등록도 동적 등록으로 스스로 한다. 그래서 사용자가 할 일은 Google 로그인과 「연결 허용」 한 번이다. fos-assistant 는 따로 Claude Code·Codex 플러그인 표준과 원격 MCP 를 받도록 바뀌고, 그 뒤 Hermes 도 이 플러그인을 쓴다. 서버에서 도는 Hermes 는 브라우저 로그인을 할 수 없어 지금의 개인 연동 토큰으로 붙는다.
- **ADR-012, ADR-013 과의 관계**: [ADR-012](012-agent-integration-token.md) 의 개인 연동 토큰, `/api/v1` 계약, 세션 경로와 Bearer 경로의 분리는 그대로다. ADR-012 가 「인가 서버, 동의 화면, refresh token 저장을 새로 만들어야 한다」 며 기각한 OAuth 는 이번에 받아들인다. 그때는 연결할 대상이 서버에서 도는 Hermes 하나였고, 지금은 토큰을 다룰 수 없는 사람이 쓰는 클라이언트가 대상이다. OAuth 접근 토큰은 `/mcp` 에서만 받고 `/api/v1` 과 세션 경로에서는 받지 않는다. [ADR-013](013-owner-trades-and-agent-proposals.md) 의 쓰기 규칙(체결은 바로 저장, 해석은 제안, 주인 전용 체결)은 MCP 도구에도 그대로 적용된다. 범위는 연동 토큰과 같은 둘(조회만, 조회와 기록)이다.
- **대안 기각**:

  | 대안 | 기각 이유 |
  | --- | --- |
  | 사용자 컴퓨터에서 도는 MCP 서버와 기기 인증(device flow) | 사용자 컴퓨터에 Node 나 Bun 이 있어야 한다. 비개발자의 Claude Code, Codex 설치에는 없을 수 있고, 버전을 맞추는 일도 사용자 몫이 된다. 도구 구현이 커넥터와 서버 두 곳에 생긴다 |
  | 연동 토큰을 복사해 플러그인 설정에 붙여 넣기 | 비개발자가 토큰을 발급하고 설정 파일이나 환경 변수에 넣어야 한다. 토큰이 대화나 화면 캡처에 남기 쉽고, 만료가 없어 새도 모른다 |
  | 도구를 커넥터에 두고 서버는 `/api/v1` 만 제공 | 도구 설명과 입력 검사가 클라이언트마다 따로 생긴다. 원격 MCP 는 서버가 도구를 가져야 성립한다 |
  | MCP 도구가 자기 `/api/v1` 을 HTTP 로 부른다 | 같은 프로세스 안에서 인증, 요청 한도, 직렬화를 두 번 탄다. 서비스를 직접 불러도 권한과 한도를 같게 둘 수 있다 |
  | OAuth 접근 토큰을 `/api/v1` 에서도 받는다 | 토큰의 대상(audience)이 `/mcp` 로 정해져 있다. MCP 규격은 다른 자원의 토큰을 받지 말라고 한다. `/api/v1` 은 연동 토큰 계약으로 충분하다 |
  | Spring Security 7 의 인가 서버(`spring-security-oauth2-authorization-server`) | resource 지시자(RFC 8707)를 지원하지 않아 대상 검사를 따로 만들어야 하고, 동적 등록한 공개 클라이언트에는 기본으로 갱신 토큰을 주지 않는다. 등록 클라이언트, 인가, 동의 저장소를 Neo4j 로 세 벌 구현해야 하고 토큰 값으로 찾는 저장소에 해시만 두기 어렵다. 쓰는 기능(동적 등록, 코드, 갱신)은 엔드포인트 넷이라 직접 만드는 쪽이 작다 |
  | Google 을 인가 서버로 그대로 쓴다 | Google 은 동적 등록과 resource 지시자를 받지 않는다. 허용 목록과 역할, 범위 고르기를 Google 동의 화면에 둘 수 없다 |
  | MCP 서버를 Spring AI 의 MCP 서버 starter 로 만든다 | Spring AI 2.0 이 Spring Boot 4.1.2 를 요구해 지금 버전(4.1.0)과 어긋나고, 자동 설정과 어노테이션 검색이 인증 필터와 요청별 사용자 전달을 감춘다. 쓰는 것은 MCP Java SDK 의 세션 없는 servlet 전송 하나다 |
  | JSON-RPC 와 MCP 를 직접 구현한다 | 프로토콜 버전 협상, 오류 코드, 도구 스키마 형식을 따라가야 한다. 공식 SDK(`io.modelcontextprotocol.sdk:mcp`)가 Jackson 3 과 servlet 전송을 지원한다 |
  | 클라이언트 ID 메타데이터 문서(CIMD) | 최신 MCP 규격이 권장하지만 동적 등록만으로 두 클라이언트가 붙는다. 다른 서버의 주소를 가져와 읽는 일이라 SSRF 방어가 필요하다. 동적 등록이 막히는 클라이언트가 생기면 더한다 |

- **결과**:
  - 얻는 것: 비개발자는 플러그인 설치 두 줄과 브라우저 로그인 한 번으로 연결한다. 토큰 원문을 보지 않는다. 도구와 설명이 서버 한 곳에 있어 Claude Code, Codex, Hermes 가 같은 도구를 쓴다. 접근 토큰은 1시간 뒤 끝나고, 갱신 토큰은 쓸 때마다 바뀌며 이전 것을 다시 쓰면 그 연결이 끊긴다. 사용자는 「더보기 → 연동」 의 「연결된 앱」 에서 연결을 보고 끊는다.
  - 감당할 것: 인가 서버 코드(등록, 동의, 코드, 토큰, 갱신, 폐기)를 이 저장소가 유지하고, MCP 인증 규격이 바뀌면 따라간다. 동적 등록은 누구나 부를 수 있어 이름을 속인 클라이언트가 동의 화면에 나올 수 있다. 그래서 동의 화면은 돌아갈 주소(이 컴퓨터의 앱인지, 어느 https 주소인지)를 함께 보이고, 등록에 IP 별 요청 한도를 두며, 한 번도 승인받지 못한 클라이언트는 하루 뒤 지운다. MCP Java SDK 2.1.0 은 MCP `2025-11-25` 까지 말한다. 세션과 `initialize` 를 없앤 최신 규격(`2026-07-28`)만 말하는 클라이언트가 생기면 SDK 를 올린다. 요청 한도는 연동 토큰과 같이 프로세스 메모리에 있다. 발급 주소(`issuer`)와 자원 주소는 요청의 scheme 과 host 로 만들어, 앞단이 `X-Forwarded-*` 를 넘겨야 공개 주소가 맞다. 플러그인의 `.mcp.json` 은 운영 공개 주소를 기본값으로 담는다. 그 주소는 이미 `scripts/deploy-prod.sh` 의 health 확인 주소로 공개돼 있고, 친구가 주소를 입력하지 않게 하려는 것이다. 운영 주소를 바꾸면 플러그인을 다시 배포해야 한다.
- **적용 범위**: 저장 모델은 [데이터 스키마](../data-schema.md) 의 「OAuth 연결」, 계약은 [API 계약](../api-contract.md) 의 「원격 MCP(`/mcp`)」, 「OAuth 인가 서버」, 「연결된 앱」, 연결 흐름과 동의 화면은 [흐름](../flow.md) 의 「앱 연결」 과 「연동」 이 소유한다. 플러그인 배치는 [코드 구조](../code-architecture.md) 의 「전체 배치」 다.
