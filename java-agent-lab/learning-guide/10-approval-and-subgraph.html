Lesson 10

사람 승인과 Subgraph

민감한 단계 전에 실행을 멈추고, 복잡해진 검토 흐름을 좁은 책임의 하위 그래프로 분리한다.

InterruptResumeSubgraphHuman in the Loop
오늘의 한 문장
중단은 오류가 아니라 그래프의 정상 상태이며, 재개는 저장된 상태에 사람의 결정을 더하는 전이다.

최종 흐름

검토 Subgraph → 계획 작성 → 평가 ─┬─ 수정 → 재평가 └─ 승인 대기 ⏸ ├─ 승인 → END └─ 수정 요청 → 계획 수정

사람 승인 실습

  1. approval과 feedback 상태의 자료형과 기본값을 정한다.
  2. 승인 노드 실행 전에 그래프가 중단되도록 컴파일 설정을 구성한다.
  3. 중단된 상태와 체크포인트를 조회한다.
  4. 승인 또는 수정 요청을 상태에 반영해 같은 스레드에서 재개한다.
  5. 승인 없이 완료 노드에 도달하지 않는지 테스트한다.

Subgraph 분리 실습

  1. 세 검토 노드와 병합 노드를 하나의 검토 하위 그래프로 묶는다.
  2. 부모 그래프가 하위 그래프에 넘길 상태와 받을 상태를 정한다.
  3. 부모 그래프에서 하위 그래프 내부 상태를 과도하게 알지 않도록 경계를 줄인다.
  4. 분리 전후 최종 결과가 같은지 통합 테스트한다.
  5. Mermaid 또는 PlantUML로 최종 그래프를 출력해 구조를 확인한다.

완료 조건

  • 승인 전에는 그래프가 완료되지 않는다.
  • 승인과 수정 요청이 서로 다른 경로로 재개된다.
  • 하위 그래프가 하나의 좁은 책임을 가진다.
  • 부모와 하위 그래프 사이의 공유 상태 키가 문서화되어 있다.
  • 최종 그래프를 그림으로 설명할 수 있다.

생각할 질문

  • 어떤 동작은 반드시 사람의 승인을 받아야 할까?
  • 승인 대기 중 애플리케이션이 재시작돼도 이어지려면 무엇이 필요한가?
  • 하위 그래프의 내부 상태를 부모 상태와 모두 공유하면 어떤 결합이 생길까?
막혔을 때 확인할 것
중단·재개와 하위 그래프 분리를 동시에 구현하지 않는다. 먼저 승인 흐름을 완성하고 테스트한 뒤 구조를 분리한다.

마지막 리뷰에 가져올 것

최종 Mermaid 그래프, 승인 전후 상태 이력, 하위 그래프 경계, 전체 테스트 결과를 보여준다.
