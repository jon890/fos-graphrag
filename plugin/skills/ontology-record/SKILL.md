# 기록과 제안

**목표: 사용자가 확인한 내용만 제안이나 체결로 올리고, 반영되는 방법을 알린다.**

## 순서

| 단계 | 할 일 | 통과 조건 |
| --- | --- | --- |
| 1 | 올릴 내용을 한 문장으로 확인받는다 | 사용자가 맞다고 답했다 |
| 2 | 올린다 | 도구 결과가 돌아왔다 |
| 3 | 다음 할 일을 알린다 | 승인 방법이나 체결 범위를 말했다 |

## 1. 올릴 내용 확인

항목 만들기, 항목 고치기, 항목 보관, 관계 잇기, 관계 보관, 주장 만들기, 투자 결정, 근거 연결, 공부 메모는 `submit_proposals` 로 올립니다.
올리기 전에 무엇을 올릴지 한 문장으로 말하고 확인을 받습니다.

> 「FLNC 를 장기 보유한다」 는 투자 결정을 근거 두 개와 이어서 제안으로 올릴까요?

사용자가 답하기 전에는 올리지 않습니다.

### 고치기와 보관

항목을 고치거나 보관하기 전에 `get_node` 로 그 항목을 읽습니다.

- 항목 고치기와 보관: 읽은 `node.revision` 을 `expectedRevision` 으로 씁니다.
- 관계 보관: 읽은 관계의 `relationshipId` 를 씁니다.

올린 뒤 `REVISION_CONFLICT` 가 오면 그사이 항목이 바뀐 것입니다. 다시 읽고 새로 올립니다.

### 주장 만들기

주장에는 근거 문서가 하나 이상 필요합니다.
근거 문서가 아직 없으면 먼저 근거 문서를 만드는 제안을 올리고, 그 문서가 반영된 뒤에 주장을 올립니다.

체결은 사용자가 직접 준 체결만 `record_trades` 로 넣습니다.
날짜, 종목, 수량, 가격을 지어내지 않습니다. 빠진 값은 사용자에게 묻습니다.

## 2. 올리기

- 제안: `submit_proposals`
- 체결: `record_trades`
- 이미 올린 것을 보려는 요청: 제안은 `list_my_proposals`, 체결은 `list_my_trades`

기록이 「조회만 허락된 연결」 이라는 이유로 거절되면 `ontology-start` 스킬의 안내대로 「더보기 → 연동」 에서 연결을 끊고 다시 로그인하게 합니다.

## 3. 알리기

- 제안: 「워크벤치의 더보기 → 제안에서 승인해야 반영됩니다」 라고 알립니다. 승인은 올린 본인이 합니다.
- 주장: 승인으로 만들어진 주장은 검토 전 상태이고, 검토는 다른 사람이 한다고 알립니다.
- 체결: 「이 체결은 나만 볼 수 있습니다」 라고 알립니다.

## 말하는 방식

- 어떤 종목을 사라거나 팔라는 권유는 하지 않습니다. 사용자가 이미 정한 결정을 기록하는 일만 합니다.
- 토큰이나 인증 같은 내부 이야기는 꺼내지 않습니다.
